# Premium UI journey verification — Kanban task details

## Scope and pre-existing implementation

The UI audit used `docs/ui/DESIGN.md`, the existing screenshot/review sets under `docs/ui/current` and `docs/ui/after`, and the current dashboard, shell, Kanban, editor, inbox, decision timeline, AI drawer and settings components. Semantic themes/tokens, shell navigation, workspace switching and command palette are already implemented. The dashboard, editor, Kanban, inbox, AI assistant and settings are existing features; this increment does not recreate them or alter backend contracts.

The selected bounded journey is the existing Kanban board to task-details drawer. The prior board review at `docs/ui/after/kanban/REVIEW.md` identified dense priority/date fields on narrow screens and focus concerns. This change makes the drawer width responsive and capped, stacks those fields on narrow screens, reuses shared input/button classes, adds explicit field labels, and restores focus to the task card that opened the drawer. If that card was removed before close, focus falls back to the board heading. Task save/delete calls and role checks remain on their existing paths.
