# Shell review loop — Phase 2b

Initial captures use real seeded owner sessions in the isolated fixture at 1440/390 in dark/light. Product text is actual API/editor data. No provider sign-in or production data is used. Images are viewport screenshots, unaltered. Shell axe scope covers navigation/topbar/skip link and open dialogs/menus/listboxes; product interiors are outside this shell audit. The 360px route test separately checks the document/shell bounds, not only CSS clipping.

## First review

- Hierarchy: document title is readable again at390px, with metadata below. Workspace/document navigation has a clear secondary hierarchy; two active links are intentional (Documents section and the actual document). Command search has no visible prompt inside its empty field: add one.
- Spacing: mobile prose is inset too far inside a second padded editor surface. Reduce its horizontal padding; retain16px page gutters. Drawer title, workspace and navigation use consistent groups.
- Contrast: dark editor AI action still uses inherited white text on the new pale-blue primary. Use primary-foreground. Shell text/token contrast looks consistent in both themes; this is distinct from whole-product WCAG certification.
- Alignment: the desktop hamburger is redundant beside the permanent sidebar. Root cause is unlayered foundation button CSS overriding responsive utility display. Put foundation rules in the components layer.
- Density: topbar contains useful actions without a notification placeholder. Mobile presence is missing; show one real online avatar, with complete identities available in desktop presence. Focus mode should hide the floating Copilot trigger.
- Consistency: no shell gradients or emoji icons; the retained editor toolbar still has older product styling. Avoid expanding this into an editor redesign. The Next dev indicator overlaps the collapse button; disable it in the development fixture, not by masking screenshots.
- Mobile: title and editor fit390px. The360px route test found overflow on the inherited overview header; allow its header groups to wrap and remove duplicated presence now that the shell owns it. Kanban retains its own board scroller; the page itself must not scroll horizontally.

Initial run is partial, not a passing suite: changing fixture dev-indicator configuration restarted Next and removed the injected axe script during the first desktop case; subsequent workers repeated beforeAll document creates, causing ambiguous duplicate labels. Fix setup to reuse the existing nested fixtures; reinject axe after a development reload. Preserve the failures and captures rather than claiming the initial suite passed. No product authorization test is relaxed.
