# ADR019: complete HTTP schema inventory without an authentication change

Status: accepted for Phase1e.

Context: route/body-generated OpenAPI explicitly omitted query and response DTOs. A route could be added without a complete contract. Operational app handlers and Next route handlers were outside the mounted router inventory. Authenticated browser evidence now provides real transport responses with which to check schema accuracy.

Decision: retain the actual request validators and all runtime authentication, authorization, signature, parsing and response behavior. Add an explicit Zod contract registry for all55 documented HTTP operations:51 mounted backend operations,2 app-level handlers and2 Next handlers. DTO scalar fields follow the installed Prisma model metadata; each controller's selected relations/projections are modeled explicitly and strictly. Requests reuse the registered body validators; search reuses its extracted, unchanged query schema. Native Stripe raw-body and Multer multipart handling remain native; their transport schemas document those boundaries. SSE includes a typed JSON event union.204 responses have no body,307 has redirect/cookie headers, signed hooks and private metrics retain their authority schemes. Correlation and GitHub delivery/event headers are described. Unsupported vector fields are not Prisma JSON fields; binary document state is described in its actual Buffer JSON representation.

Generation rejects unknown mounted routes, missing mutating request schemas (except explicitly ignored bodies), empty response sets and responses without schemas. Existing `x-validation-complete:false` remains truthful and its prior test is retained: not every route runs generic request/query/response validation middleware. `x-contract-complete:true` separately records the complete documentation schema. No HTTP response parser was inserted into production. The cookie-reset route's inherited arbitrary redirect behavior is documented, not repaired in this group.

Native recursive JSON Schema references must be relocated to their OpenAPI component path. A test resolves every local reference; leaving a native root `#` inside an embedded response would incorrectly refer to the whole OpenAPI document. Independent TypeScript AST inventories guard app-level and Next handlers; a mounted test router without a contract and a mutating router without a body validator both fail. Orphaned registry entries fail too.

Verification: actual HTTP responses for resource CRUD, profiles, search, invitation operations, private administrative operations, repository configuration, signed GitHub/Stripe events and SCIM are parsed by the DTO schemas in the isolated Playwright harness. Existing ten product journeys remain. This is transport evidence, not proof of every provider delivery, every SSE provider outcome or real Clerk sign-in. The harness uses ephemeral signing/service credentials and no billable external provider requests. The new signed-hook scenario exposed an outer fixture JSON parser consuming raw bytes; parsing is now confined to fixture-login endpoints so actual app routes own raw-body capture. Production parsing is unchanged.
