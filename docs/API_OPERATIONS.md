# Phase1e contract coverage

`backend/openapi.json` now covers all 55 inventoried HTTP operations, with Zod path/query/body transport schemas, response DTOs/statuses, multipart upload, SSE event data, signatures, correlation headers and bodyless/redirect responses. Legacy backend aliases are declared alongside v1 paths. The2 frontend operations identify the frontend origin separately. Backend mounted routes fail generation if a contract is absent; independent AST tests guard app-level and Next handlers. `npm run openapi:check` checks the committed artifact.

`x-contract-complete:true` describes schema documentation coverage. `x-validation-complete:false` is deliberately retained: production does not run a universal output validator, native Stripe/Multer boundaries are preserved, and ignored request bodies remain ignored. This change does not alter authorization or add an auth bypass. See ADR019 and phase1e-evidence/ for actual validation output. Provider success and real Clerk sign-in must not be inferred from the isolated fixture.

# Phase 1b API and telemetry

The same protected routers are mounted at `/api/v1` and the existing `/api` paths. SCIM retains `/scim/v2`; webhook aliases preserve signed raw-body validation. Legacy application routes emit a Deprecation date of 2026-11-01. There is no automatic removal: retain aliases until clients have migrated and a separately reviewed release supplies at least 90 days of notice. Operational `/api/health` and `/api/ready` probes remain supported. Track alias usage without logging query strings or workspace/document content.

Use Node22.12+ (on the 22 line), Node24 or Node26+ for the current test/metrics toolchain; Docker and CI use Node22.

Every Express request receives a server-generated UUID in `X-Request-ID`, including parser failures and 404s. HTTP JSON failures preserve the prior `error` string and other fields, adding stable `code` and `requestId`. Internal errors expose no stack or exception message. Streaming AI failures use their SSE error event and correlation ID. Client code using the original string remains compatible. Unhandled errors after headers are sent close the response through Express's error path.

`/api/health` (and `/api/v1/health`) is liveness. Readiness at the corresponding `/ready` path checks a real PostgreSQL transaction, Redis PING and the preexisting required configuration presence, returns 503 when draining/unavailable, and bounds its response with a deadline. Redis probes use short-lived independent clients, not unbounded BullMQ command retries. Readiness is not a proof of valid external Clerk credentials. Configure sensible database connection/pool timeouts as well as the probe deadline.

SIGINT/SIGTERM stop admission, flush collaboration, close Socket.io/HTTP, Redis and Prisma, then telemetry/reporting. Repeated signals share one drain. Unexpected asynchronous failures also drain and exit. Cleanup attempts continue if one component fails. A 15-second hard deadline terminates the process with failure; acknowledged document updates remain in the durable journal. Existing worker lifecycle/logging still needs a separate review.

## Contracts

`/api/docs` serves OpenAPI 3.1 JSON. `npm run openapi:generate` regenerates `backend/openapi.json` from mounted routers and Zod middleware body schemas; `npm run openapi:check` and the backend regression test reject drift. This is a partial contract: query/response schemas and some bespoke route validators are not registered. Each operation explicitly reports `x-validation-complete: false`; unrepresented fields are not evidence of validation. Authentication scheme descriptions do not replace authorization checks. Current durable create routes accept optional `Idempotency-Key` (1–128 printable ASCII characters): workspace, document, snippet, board, column, task, registered-member invite, repository, ingestion and SCIM user creation. The same verified authority/logical operation/scope/key and validated JSON replay the original201 response for24 hours. Legacy/v1 aliases share scope. A different payload returns409; current authorization is always checked before replay. Resource, activity, outbox and RLS-protected receipt share one PostgreSQL transaction, so a crash or receipt error cannot commit only the resource. Repository secrets and raw request/key data are not copied into receipts. Upload hashes include bytes, MIME and filename; OCR can still run twice before the atomic final transaction. Webhooks use provider delivery IDs, identity sync provider-ID upserts and streaming AI its separate usage protocol. These are not cached-create claims.

Expired keys can create a new resource after the retry window. Active authorities receive bounded opportunistic cleanup. Schedule privileged maintenance to delete expired `ApiIdempotencyRecord` rows for inactive authorities; runtime receipt reads require transaction-local authority context and must never bypass that RLS policy. Take normal database backups and use the new forward migration before deploying keyed creates. ADR016 explains the transaction and retention decisions.

## Safe optional telemetry

- `LOG_LEVEL` controls pino HTTP/system logging. AsyncLocalStorage preserves correlation across asynchronous operations; background work uses the system identifier. HTTP serializers allow only request ID, method, response status and timing. They omit bodies, headers, URL/query strings and raw exceptions. Existing legacy console statements remain outside this migration; full logging compliance is unfinished.
- OTLP tracing starts only with `OTEL_EXPORTER_OTLP_ENDPOINT` and without `OTEL_SDK_DISABLED=true`. HTTP/Express, PostgreSQL and supported ioredis instrumentation plus tenant-transaction/AI spans are enabled. Export filters allow only operation/status/correlation attributes, clear exception events/links/status messages, and disable automatic process/host resource detection. Prisma engine and ioredis6 automatic span coverage is not claimed; tenant transactions have explicit spans.
- `SENTRY_DSN` is optional and empty by default. Only manually reported generic internal errors are sent, with request IDs. Automatic integrations and user/cookie/header/body/query/AI/database-payload collection are disabled; event request/user/extra/breadcrumb data is removed. Reporter and tracing collector infrastructure/retention remain operator responsibilities.
- `/metrics` returns 404 when `METRICS_BEARER_TOKEN` is empty/shorter than 32 characters, 403 without its exact bearer value, and Prometheus exposition when authorized. Keep the secret private and rotate it through deployment configuration. Counters cover HTTP counts/latency and AI provider calls/errors; gauges cover document connections and loaded rooms on this instance. Labels use route templates and fixed categories, never raw paths, principals, document IDs or prompts. Collect per instance and aggregate in the monitoring system. Socket.io connection gauges are not yet included.

New telemetry and reliability regression tests exercise real HTTP listeners, database/Redis outages, request/exception redaction, OpenAPI drift, shutdown ordering/deadline and an actual local OTLP collector. Test outcomes, including failures/retries, belong to `phase1b-evidence/`; do not infer success from this operations guide.
