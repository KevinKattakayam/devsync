## Atomic snapshot storage primitive — integration pending

`frontend/src/lib/draft-storage.ts` opens the existing `updates`/`custom` schema and provides read/commit primitives. Readwrite transactions merge existing updates with the incoming Yjs snapshot and compact to one update atomically. Concurrent connections serialize through IndexedDB. The write promise resolves only from `transaction.oncomplete`; abort rejects with a typed reason. An 8 MiB merged-state cap, 1024-record scan cap and 16 MiB aggregate input cap bound a call. Over-limit/corrupt legacy data remains intact rather than being deleted. These bounds do not yet cap live editor storage or total storage across documents.

Five focused fake-indexeddb tests cover independent connections, previous-state retention on limit refusal, compatibility with actual y-indexeddb-produced records, simulated quota rollback and closed/denied storage. The initial tests failed before implementation; an intermediate cross-realm Uint8Array detection failure was corrected with typed-array view validation. Simulated quota is not real browser capacity evidence. This library has no production caller yet; no editor acknowledgement, purge, upload or restore behavior changed.

Remaining engineering: integrate a bounded writer into the hook while preserving hydration/compaction and current room/account scoping; expose its status without confusing it with remote acknowledgement; test true browser quota/termination behavior; design coordinated purge/tombstone behavior preventing other tabs from repopulating a cleared store; gate any restoration on fresh authorization and safe CRDT merge. Existing y-indexeddb continues to be the live adapter until that integration is verified. Phase 12 is incomplete.
