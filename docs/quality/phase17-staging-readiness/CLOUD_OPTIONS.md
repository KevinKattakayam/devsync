## Comparison and concrete unknowns

**Render Free comparison, 14 November 2026:** Render Free web services support WebSockets but sleep after 15 minutes without incoming HTTP or WebSocket messages; waking takes about a minute. Render's free instances do not include background workers, and free Key Value is memory-only and loses data on restart. Its free web services also cannot attach persistent disks. See [Render's free-tier documentation](https://render.com/docs/free). DevSync's separate `backend/src/worker.ts` consumes BullMQ embedding, task-completion, PR-summary and optionally automation queues; `backend/src/lib/queue.ts` stores queued jobs and dead letters in Redis, and `backend/src/services/ai-quota.ts` uses Redis for quota counters. Losing free Key Value state is therefore not equivalent to clearing a disposable cache. Running the worker alongside a free web service would not provide continuous processing through spin-down and would not supply durable Redis. This option does not meet the current requirement to retain functionality and data-integrity controls. Render supports receiving WebSocket messages while active; it is not accurate to say WebSockets are unsupported.
