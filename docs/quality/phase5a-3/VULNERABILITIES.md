## Rebuilt images and accepted risks

Final backend:0 Critical/44 High/75 Medium/60 Low/8 Unknown. Final frontend:0 Critical/44 High/71 Medium/60 Low/8 Unknown. These are scanner package/advisory entries, not exploits. The Critical is removed; gzip and two util-linux CVEs from the old inventory are fixed in Trixie. **High counts increase32→44 per image**, because newer util-linux features carry additional unpatched CVEs, an additional source-package footprint is present, and SQLite is now reported. This is not an across-the-board vulnerability-count improvement. Raw initial/final reports are retained, not severity-filtered.

Per the user's Phase5a-3 instruction, remaining entries are **accepted risks for the documented hardened runtime**, not hidden or asserted globally unexploitable. The supported Trixie package fix is absent from both the raw scan and the linked Debian tracker at review. Where a patch exists upstream/unstable, it is listed explicitly; no claim that no patch exists anywhere. Mixing unstable libc/OS packages or doing an unpinned apt-get upgrade was not chosen. Reassess these acceptances when a stable-suite/base update is available, or before changing runtime identity, capabilities, privilege policy, tool availability or exposed data paths.

Both images retain dpkg metadata. No Trivy ignore file, severity downgrade, VEX suppression or CI threshold change. Therefore the existing High/Critical CI gate still fails on these raw High entries; this document does not fabricate a green hosted release.

The final isolated Compose test verifies API/frontend/worker UID1000, CAP_SYS_ADMIN absent, no-new-privileges enabled, no fstab entries, mount/umount/nsenter executables absent and infocmp absent in API/frontend. systemd-homed/homectl and the Perl Archive::Tar module are absent. Bootstrap/migration targets retain their tools; they do not run user-facing requests. Raw probes are in compose/*-runtime.json. No exploit, hostile native payload or production host assessment was run.
