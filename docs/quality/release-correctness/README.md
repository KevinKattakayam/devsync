## Source changes and compatibility

- Authentication sync strictly parses bearer authorization and classifies installed Clerk SDK rejection reasons. Invalid/expired/not-yet-active tokens deny with a redacted401; key-resolution/configuration failures deny with503. Profile/database failures retain ordinary error handling. No clock tolerance or authority was relaxed. Tests use SDK error fixtures, not real Clerk sessions.
- Stale-session GET retains its307/local redirect but performs no cookie mutation. The additive POST requires exact canonical Origin and rejects cross-site Fetch Metadata; it clears only Clerk identity cookies and redirects303. Forms use POST. `AUTH_TRUSTED_ORIGIN` supplies the operator-controlled public origin behind proxies; it never derives authority from caller-supplied Host/forwarding headers. This clears local cookies, not provider sessions. OpenAPI records the security migration.
- Every effective document journal append queues the existing tenant-bound embedding outbox in the same writer-authorized transaction. Duplicate state creates no revision or job churn; compaction preserves a completed embedding hash. A membership-change race denies persistence and closes the transport. Existing wire contracts and forward migrations remain intact. A queued job is not a completed/live-provider embedding, and continuous edits can still postpone successful indexing.
- Binary ingestion runs through a bounded adapter into a separate credential-free extractor. Text ingestion remains local. Without a configured worker binary ingestion returns503; there is no host parsing fallback. Compose supplies a non-root, read-only, internal-network service with512MiB memory, one CPU,64 PIDs and64MiB temporary storage. One request runs at a time; the30-second parent deadline kills its child. Input25MiB, PDFs20 pages, declared image dimensions16 million pixels and output256KiB are bounded. Aggregate native allocation is constrained by the container, not just the V8 heap. The pinned local English OCR model avoids model downloads during extraction. This container boundary is not a claim of immunity to parser/container/kernel vulnerabilities.
- The frontend upload uses the configured API client, existing token interceptor and multipart boundaries rather than hardcoded localhost. No file URL or worker destination is accepted from document content.
- Sentry11.11.0 selects glob14.0.4/minimatch11.0.5. A scoped gcp-metadata8.1.4 override selects same-major gaxios7.3.1, removing its rimraf/glob runtime chain. image-size2.1.0, the existing Clerk backend3.13.2 and offline model1.0.0 are explicit pins; lockfile integrity is retained. See `alpine-zlib-policy.txt` and final image scans. Actual GCP metadata discovery is not verified.
- CI includes the extractor as a separately scanned/SBOM/published artifact with the existing High/Critical gate. No coverage floor, scanner severity, test assertion, visual baseline or authentication/RLS control was lowered.
- History scanning exposed two occurrences of the public webhook-test sentinel in the scanner regression generator. The added exception requires both its exact non-credential value and exact generator path. Seven regression cases preserve new-value and other-path detection. No credential class or entire file is excluded. Initial and final redacted scan reports are retained.
