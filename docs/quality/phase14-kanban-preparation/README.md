## Native drag lifecycle cleanup follow-up

The task card now owns only its transient visual `isDragging` boolean and clears it on native `dragend`; unmounting a deleted or moved card discards that local state. The page no longer retains a task object or task ID for a drag. It reads the ID already placed in `DataTransfer` at drop time and resolves it against the current rendered board through the existing move guard, so stale/deleted task IDs and current permission are rechecked before moving. A permission change also hides the dragging visual while write access is false. The Yjs optimistic move, `taskApi.move`, refetch-on-failure and server authorization behavior are unchanged. No document-wide keyboard listener or additional drag architecture was introduced.

Focused React tests passed: 2 files / 9 tests. The standalone Chrome fixture using the actual extracted TaskCard and move guard passed at 1440px and 390px: pointer drop, Escape cancellation with zero drop, a successful drag/drop immediately after cancellation, keyboard Radix Move, Drawer focus return, simulated task deletion, simulated permission revocation, and updated task data. Axe reported zero violations and zero incomplete checks in the tested initial state at both widths. Vite emitted unresolved optional `esbuild`/devtools import warnings; the server and browser script nevertheless ran and the check exited 0. Results are in `browser-fixture/results-drag-cleanup.jsonl`.

These browser checks use controlled fixture state only. They do not prove live Yjs persistence, API rejection/rollback, tenant authorization or Testcontainers integration. If a browser omits native `dragend` on Escape while the source card remains mounted, the visual `isDragging` state may remain until that card unmounts or a later dragend; pointer/move actions and every drop still use the current authorization guard. Source deletion/move unmounts the card and discards that local state, and page unmount also discards it. No manual screen-reader review was performed. Virtualization remains unimplemented and Phase 14 remains open.
