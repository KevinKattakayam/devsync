## Mandatory criteria versus deferrals

The original Phase 13 definition of done requires Markdown/task round-trip, malicious input rejection, no active HTML/script handling, tenant-isolated exports, and accurate workspace-scoped archive labeling. These are verified above. It does not require archive restore/import or account-wide erasure. Archive restore/import is therefore deferred; adding it requires a separate safe import design and authorization lifecycle. Broad CommonMark/rich-text import/export is also deferred: the current contract deliberately supports paragraphs and ATX headings and rejects unsupported structures instead of dropping or reinterpreting content. PDF shares that supported subset.

Other explicit limits: the archive contains only supported document Markdown and task CSV v1; it excludes account, membership, credentials, metadata, snippets, decisions, GitHub state and other resources. Included content may still contain sensitive information. There is no archive encryption, redaction, account-wide export/erasure, or server-side retained artifact. The import APIs are synchronous; there are no asynchronous import jobs needing cancellation. Task CSV import has a dedicated per-process rate limit, and all APIs also pass through the existing general request limiter.

Real Clerk identity acceptance was not a Phase 13 mandatory criterion and was not performed. No real provider account was used. The existing fixtures and disposable databases are correctly labeled in test evidence. No production data was changed, and no push, deployment or Phase 14 work occurred.
