# Workspace archive export verification

`GET /api/v1/workspaces/{id}/archive.zip` (and the existing `/api` alias) returns a workspace-scoped ZIP to active owners, editors and viewers. A tenant transaction reads supported non-archived documents from the committed CRDT journal and task CSV v1 from the existing serializer. Compression occurs outside the transaction. A second authorized snapshot checks membership, suspension, document visibility and source fingerprints before any bytes are sent; a changed source is rejected.

The version 1 manifest identifies included and excluded resource categories, generated entry paths, byte lengths and SHA-256 hashes. Paths are `documents/000001.md`, etc. and `tasks/tasks.csv`; titles or user-provided names are never used as paths. Document titles and other document metadata, task keys/labels and other task metadata, account data, members, integration credentials and other workspace resources are excluded. The archive is not a complete account backup. Content is unencrypted and not redacted; documents or task fields may themselves contain sensitive information. No archive is retained on the server.

Limits: 100 documents; 256 KiB per document; 1,000 tasks and 1 MiB task CSV; 8 MiB total input and 8 MiB ZIP output; 10 seconds for compression. The existing tenant transaction has a 15-second timeout per snapshot; there is no single deadline covering both snapshots and compression. Unsupported document structures, excessive size or changed data fail without delivering a partial archive. Task, column and board schemas have no archived flag; deleted tasks are not exported. There is no archive import or restore.
