## Follow-on inbox, preferences and failure evidence

The feature-flagged inbox route uses the existing digest Activity window and individual read markers. The separate automation-failures endpoint reuses the owner-only automation execution reader and current task/GitHub source checks; nonowners receive no failure data. Failure times come from existing audit entries, and personal read state uses a new forced-RLS table with a workspace/execution composite foreign key. The view is limited to failures among the latest 100 executions. Disabled automation returns no failure items. Provider events and job failures do not establish delivery or deployment.

Personal notification settings persist a validated timezone, optional paired quiet hours and an interval of 15, 60 or 1440 minutes under tenant/actor RLS. The read-only batch preview uses authorized, unread Activity from one digest page, up to 25 events per batch, and computes quiet-hour boundaries in local time including DST. It excludes automation failures and schedules no delivery. The UI states that email, push and scheduled delivery are inactive. This is not a durable batch worker or provider adapter.

The inbox and digest clear visible records when disconnected or hidden and revalidate on reconnect, focus or tab return. Source navigation opens existing authorized resources; no provider result is fabricated. The inbox continues to use the digest's seven-day window and acknowledgement checkpoint. The browser and integration identities are fixtures, not live Clerk or GitHub verification.
