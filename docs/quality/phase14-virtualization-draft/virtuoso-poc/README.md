# Isolated Virtuoso interaction proof of concept

This fixture is not integrated into DevSync. It uses 1,000 synthetic tasks, React Virtuoso 4.18.21 and the repository's installed dnd-kit 6.3.1. The JSONL files contain assertion-based observations from local Chrome at 1440px and 390px; no workspace API, real user data or provider was used.

`native-drag.tsx` exercises Virtuoso's documented `computeItemKey` and `scrollIntoView` APIs with a responsive long row, native HTML drag, a simplified drawer and a drop target. `native-drag-check.cjs` checks measured-height changes, keyboard access to the first task, offscreen scrolling, keyboard close/focus restoration and a pointer drop after source unmount. `native-cancel.cjs` checks Escape after source unmount. At both widths, the focused task unmounted and focus moved to `BODY`; the simplified drawer restored focus after scrolling back. The native drop reached the target, but the fixture's source `dragend` handler did not run. On cancellation its fixture state remained marked as dragging. These observations do not prove the exact behavior of the real board.

`overlay.tsx` replaces the fixture's native drag path with dnd-kit's `DndContext`, pointer sensor and `DragOverlay`. `overlay-check.cjs` verifies the overlay remains visible after the source unmounts, a pointer drop moves the synthetic item to the end, and Escape clears the overlay. At both widths 9 rows were initially and subsequently mounted. This is evidence for an overlay experiment, not a verified replacement for the board's native drag, keyboard move, permissions or persistence.

The native fixture rendered 5–6 initial and 3–6 final task rows; its long row measured 114px at desktop width and 150px at mobile width during resize. `native-results.jsonl`, `native-cancel-results.jsonl` and `overlay-results.jsonl` contain the exact local observations. The tests demonstrate initial Tab access, not full screen-reader or sequential traversal of every offscreen task.

Focused ESLint, strict TypeScript and the isolated `component-test.tsx` passed after temporarily resolving Virtuoso and its React peer to the repository's React instance. An initial component run failed because the temporary installation loaded a second React copy; it passed after that temporary wiring was corrected. No full application gate was rerun: the preserved TanStack integration still fails the required lint gate. The repository does not enable React Compiler, so these checks do not prove compatibility under an enabled compiler.

To reproduce in this workspace, install `react-virtuoso@4.18.21`, `react@19.2.4` and `react-dom@19.2.4` under `/tmp/devsync-virtuoso-probe`, copy `index.html`, `vite.config.mjs` and either fixture source as `main.tsx` there, then start `frontend/node_modules/.bin/vite /tmp/devsync-virtuoso-probe --host 127.0.0.1 --port 3419 --strictPort`. Run the corresponding `.cjs` checks with `POC_WIDTH=1440` and `POC_WIDTH=390`; they use the local Chrome and Playwright paths shown in the scripts. The component test is copied temporarily into `frontend/tests` with `overlay.tsx` copied as `frontend/src/virtuoso-overlay-poc.tsx` and a temporary Virtuoso symlink; React must resolve to a single instance. Remove only those temporary copies and symlink afterward.

The public [dnd-kit overlay guidance](https://dndkit.com/legacy/api-documentation/draggable/drag-overlay/) recommends an overlay when a virtualized drag source unmounts. Integrating that pattern requires replacing the existing board's native drag handling and verifying its full interaction and authorization behavior. More importantly, the fixture still loses focused-row focus during user scrolling. No production replacement is selected until an accessible, bounded strategy preserves that interaction and the remaining move, drawer, resize and permission cases pass.
