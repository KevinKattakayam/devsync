## Delivered behavior

`GET /api/v2/workspaces/:workspaceId/search` accepts bounded `q`, `limit`, optional `type`, `assigneeId`, `after`, `before`. It performs central active-principal/current-member/unsuspended-workspace policy and tenant RLS before reading results. Source types are document, task, snippet, decision and pull_request. Assignee filtering intentionally returns tasks only. Time boundaries are inclusive UTC instants (offset ISO input is accepted); reversed ranges fail400. Local-resource timestamp-without-timezone values are explicitly interpreted as UTC before combining with GitHub timestamptz values, and bounds are explicitly cast from their validated offset-qualified strings. A real Asia/Kolkata session regression covers the exact boundary. Full-text queries use parameterized `websearch_to_tsquery('simple', ...)`, deterministic rank/time/type/ID ordering and at most50 results. Whole-word lexical syntax supports phrases/OR/negation; this is not fuzzy/substring completion.

`GET .../search/source?type=...&id=...` repeats every workspace and source check. Foreign, absent, archived, disconnected or role-hidden source IDs return404 without titles; revoked workspace membership returns403. Even an owner cannot bind a receipt to a document in a different tenant. Readers include OWNER/EDITOR/VIEWER for local resources; recorded PR metadata retains OWNER-only authority. Receipt and snippet-safety feature flags remain authoritative behavior gates. Snippet text is masked before disclosure when the existing safety flag is enabled. No external write capability is introduced.

Both routes send `Cache-Control: no-store`. There is no server search cache or derivative content store. The browser clears prior results on a failed search/open, page hiding/focus and request replacement; generation fencing ignores late responses. Source-open requests recheck current access before navigation, and destination APIs retain their own policy. Existing task/snippet/receipt destinations are their existing collection screens; document navigation is exact. Browser state already disclosed to an authorized user cannot be remotely erased. The unrelated sidebar document-tree refresh behavior is not a search cache or an immediate archive-purge guarantee.

Every v2 result is explicitly `method: lexical`, `freshness: current_projection`. `updatedAt` describes the committed source row; `indexedAt` is the read-time lexical projection evaluation timestamp, equal to `retrievedAt`, **not** a persisted GIN-build timestamp, embedding completion, provider acknowledgment or original provider timestamp. GIN index maintenance belongs to the source transaction, with no async lexical worker. Recorded PR update time is the local evidence observation time. Unsent, offline and unacknowledged browser edits are not searchable. Previously deployed/externally modified inconsistent projections are not silently repaired or overwritten by search.

The v2 UI deliberately performs lexical search without calling an AI provider: `semantic: not_requested`. Optional pgvector retrieval continues through the preserved legacy/AI path, separately from these lexical results. It now excludes null/invalidated embedding hashes. Missing keys/provider rejection still fall back through the existing legacy path; the new page needs neither AI credentials nor a successful embedding job. No receipt/PR embedding producer, mixed-score ranking or new embedding store was added. Legacy semantic DTOs remain unchanged and do not gain a fabricated index timestamp/navigation ID. Existing valid vectors are not bulk regenerated; their next authorized outbox job uses plain body text. Prior JSON string document bodies remain supported.

## Migration and rollback

`backend/prisma/migrations/202611080003_search_text/migration.sql` is transactional additive DDL: one immutable, non-security-definer TipTap plain-text function and four expression GIN indexes over existing document/snippet/task/receipt rows. It copies no source content and changes no tenant policy, table row, credential, grant or WebSocket/API contract. It reads only text/content nodes (and legacy strings), excluding editor attributes. Existing fresh-database migration and runtime RLS tests exercise it.

Apply with the existing privileged migration/backup procedure in RUNBOOK; never deploy/migrate production implicitly. Standard CREATE INDEX takes write locks and reads existing rows, so operators must assess table size, disk space and a maintenance window before rollout. Production planner/index use, large-document PostgreSQL tsvector limits, language segmentation and capacity are not benchmarked or certified. Do not mark functions leakproof or bypass RLS to force a query plan. A future concurrent-index rollout requires a separately reviewed operational migration.

Retain this function/index schema on application rollback: the repaired legacy search also calls the function. Revert application use through a reviewed release if needed; do not drop tables/indexes or overwrite CRDT data as a rollback shortcut. No data conversion or reverse data mutation is required. Existing decision/snippet flags remain unchanged; the new read-only lexical endpoint itself is not feature-flagged. No production backfill/reembedding was run.
